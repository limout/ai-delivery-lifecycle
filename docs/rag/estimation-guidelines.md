# Estimation guidelines (demo)

Synthetic rules of thumb for the Copilot demo knowledge base.

## Uncertainty

Estimates are ranges, not commitments. Confidence stays low when integrations, first-release scope, or team capacity are unnamed. A single-point date in a proposal does not make the range disappear.

## Dependencies

External system access, vendor SLAs, and environment provisioning sit on the critical path more often than coding. If a dependency has no owner, widen the duration range rather than assuming parallel work.

## Buffers

Do not hide buffer inside fake precision. State the range, then state what would move the high end: late API access, extra locale, extra approval gate.

## Scope changes

New reports, extra roles, and “just one more integration” are scope. Capture them as change, not as the original estimate being wrong. AI-assisted faster coding does not automatically absorb extra scope.
